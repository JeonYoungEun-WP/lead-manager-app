## 0. 스코프 — 반드시 필터

**집계 대상 = CPR+ · CPA+ (위픽 콜센터가 상담하는 상품)만.**
CPA(광고주가 데이터만 받아감)는 부스터에서 상담하지 않아 상태값이 연락대기에 머무름 → 섞으면 모든 지표가 왜곡. `product_type` 필터 전제.
CPS(고객사 상담사)는 별도 결정 전까지 제외.

## 1. 원자 카운트

| 카운트 | +1 시점 | 주의 |
|---|---|---|
| **DB수** | 리드 폼 제출 → 연락대기 진입 | 1리드 = 1 |
| **무효DB수** | 상태값 = 결번·중복신청·사전중복·불량·테스트·리워드 | DB수의 부분집합 |
| **유효DB수** | DB수 − 무효DB수 | 모든 전환율의 기본 분모 |
| **콜터치수** | 콜 **발신 1건**마다 +1 | 연결 무관, 재콜도 매번 +1 |
| **통화연결수** | 콜이 실제 통화로 연결 | **통화거절(1초 끊김) = 연결 아님** |
| **예약수** | 상태값 "예약성공" 진입 | 취소 후 재예약 중복 카운트 금지 (최종 상태) |
| **방문수** | 방문완료 진입 | CPR+/CPA+ 책임 범위 밖일 수 있음 — 미집계 시 표시 방침 별도 결정 |

## 2. 화면 구성 (최종 확정)

### 2.1 랜딩별 — 리드·광고주 관점 (단일 화면, 토글 없음)

**퍼널**: 유효DB → 통화연결 → 예약 → 방문
- 단계 카드의 % = ÷직전 단계 (병목 확인)
- 가로 막대 각 칸의 % = **÷유효DB 누적 전환율** (최종 ROI)
- 막대: 높이 64px, 2줄(라벨/큰 %), 유효DB 칸은 "100%" 흐림 처리

**테이블 컬럼**: 브랜드 · 랜딩 · 총DB · 무효 · 유효DB · 콜터치수 · **유효당 콜터치**(노력 밀도, ≥2 주황) · 통화연결(÷유효DB) · 예약(÷유효DB) · 방문(÷예약)
- 모든 비율 = 건수(위)+%(아래) 2줄
- ~~활동 기준 토글~~ 제거됨 — 노력 밀도는 열로 흡수
- ~~첫 연락 열~~ 제거됨 — 응대 속도는 상담사별 카드 이행이 담당

### 2.2 상담사별 — 콜센터 관리 관점

**① 매니저 요약 (최상단)**
- 4분면 산점도: X=노력(카드 이행률 3종 평균), Y=성과(리드당 예약성공률), 기준선=팀 평균
- 분면: ①모범(노력↑성과↑) ②효율형(노력↓성과↑) ③노력형(노력↑성과↓→스킬 코칭) ④위험(노력↓성과↓→행동 교정)
- 상관 자동 판정: 카드 이행 상위 3명 ∩ 예약률 상위 3명 → 3명=강함 / 2명=있음 / ≤1명=약함
- 주의 문구 고정: "상관≠인과, 표본 작으면 분기 누적 확인"

**② 지표별 비교 그래프**: 연결율(÷콜터치, 0~100) · 예약율(÷연결, 0~30) · 유효당 콜터치(0~5) — 각 지표 1위 👑+진한 막대, 나머지 45% 투명

**③ 테이블 3그룹**

| 그룹 | 컬럼 | 분모 |
|---|---|---|
| **성과** (파란 배경) | 배정총리드 · 유효리드 · **리드당 예약성공률** | 예약수 ÷ 유효리드 (건수+% 2줄) |
| **활동** | 유효당콜터치 · 콜터치수 · 통화연결 · 예약 · 방문 | ÷콜터치 / ÷연결 / ÷예약 |
| **카드 이행** | 신규 30분 컨택률 · 부재중 재컨택률 · 가망 재컨택률 | 이행÷발생 (아래 §3) |

- 배정·유효리드 = original_owner 기준 (본인이 처음 배정받은 리드)
- ~~신규/이관 분리 컬럼~~ 제거됨 (사용자 결정)
- ~~SLA·첫연락시간·약속이행률~~ → 카드 이행 3지표로 대체

## 3. 카드 이행 판정 (액션카드 연동)

| 카드 | 발생 조건 | 이행 판정 |
|---|---|---|
| **신규 30분 컨택** | 신규 리드 인입 | 인입 +30분 내 첫 콜 시도 |
| **부재중 재컨택** | 부재중 상태 진입 | 카드 발생 **당일 내** 콜 시도 |
| **가망 재컨택** | 재연락(1회 이상 연결) 상태 | 카드 발생 **당일 내** 콜 시도. 콜백 약속 시각 있으면 **±30분** |

- 표기: 이행/발생 건수(위) + %(아래). 색: ≥80% 초록 / 60~79% 주황 / <60% 빨강. 발생 0건 = "—"
- 콜 시각 = 통화앱 자동 기록 (수동 입력 아님 — 조작 불가)

## 5. 개발 착수 전 체크리스트

- [ ] product_type 필터: CPR+/CPA+만 집계 — CPA 혼입 시 전 지표 왜곡
- [ ] 콜터치 = 발신 1건당 +1 (연결 무관) — 통화앱 로그 확인
- [ ] 통화거절(1초) = 연결 아님 — 분류 로직
- [ ] 무효DB 6종 (결번·중복신청·사전중복·불량·테스트·리워드) 범위 확정
- [ ] 액션카드 발생 이벤트가 카드 이행 판정의 기준 시각 — 카드 테이블/이벤트 스키마 확인
- [ ] 콜 시도 시각 = 통화앱 자동 기록 연동
- [ ] original_owner 배정 이력 존재 확인
- [ ] 방문 상태값: CPR+/CPA+ 범위 밖이면 "—" 표시 방침
- [ ] 4분면·상관 판정은 프론트 계산 (HTML 로직 그대로 이식)
